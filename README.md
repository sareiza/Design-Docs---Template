# 🛠️ Design Docs - Template

Una plantilla modular y estandarizada para la creación de **Documentos de Diseño Técnico (Design Docs / Technical Specs)** en proyectos de desarrollo de software. 

Diseñada para servir como la arquitectura inicial y guía base de planificación en cada nuevo proyecto o repositorio en el que trabajes, permitiendo definir el alcance, arquitectura, métricas y decisiones técnicas antes de iniciar la fase de codificación.

---

## 📌 Origen e Inspiración

Esta plantilla está inspirada directamente en la metodología y guía práctica propuesta por **[freeCodeCamp.org](https://www.freecodecamp.org/)** en su artículo:
👉 [How to Write a Good Software Design Document](https://www.freecodecamp.org/news/how-to-write-a-good-software-design-document-66fcf019569c/)

Partiendo de esta estructura de referencia, la plantilla ha sido adaptada e independizada para separar claramente puntos clave como las **No Metas (No Goals)**, la evaluación de **Sistemas Existentes / Competencia** y el seguimiento detallado de **Hitos (Milestones)** y **Cronograma**.

---

## 📐 Estructura de la Plantilla

La plantilla cuenta con las siguientes secciones organizadas de alto a bajo nivel:

1. **Encabezado / Metadata:** Título, Autores, Revisores y fecha de última actualización.
2. **Overview / Descripción General:** Resumen de alto nivel (máximo 3 párrafos).
3. **Context:** Contexto del problema, necesidad del proyecto y alineación con objetivos.
4. **Goals & No Goals:** Impacto esperado, métricas de éxito y delimitación estricta de lo que **no** se resolverá para evitar el *scope creep*.
5. **Milestones:** Puntos de control y fechas estimadas clave.
6. **Existing Solution:** Análisis del sistema actual a migrar o evaluación de soluciones existentes en el mercado (puntos fuertes, débiles y ausentes).
7. **Proposed Solution:** Arquitectura técnica detallada, historias de usuario y diagramas.
8. **Alternative Solutions:** Evaluación de alternativas consideradas (Pros y Contras).
9. **Testability, Monitoring and Alerting:** Estrategia de pruebas y monitoreo en producción.
10. **Cross-Team Impact:** Impacto en rendimiento, costos, seguridad y equipos operativos.
11. **Risk-Matrix:** Análisis de los riesgos que puede conllevar el desarrollo del proyecto y como afrontarlos.
12. **Open Questions:** Registro de "incógnitas conocidas" e incertidumbres pendientes.
13. **Detailed Scoping and Timeline:** Desglose fino de tareas y cronograma para ejecución.
14. **Discussions:** Consolidado de desacuerdos técnicos y debates clave.

---

## 🚀 ¿Cómo utilizar este repositorio?

1. Haz **Fork** o clona este repositorio.
2. Copia el archivo de la plantilla (`template.md` o el archivo principal) al directorio del proyecto en el que vayas a trabajar.
3. Completa las secciones según las necesidades específicas de la arquitectura a diseñar.
4. Utiliza las secciones de discusión y revisión antes de dar por aprobado el diseño final.
